# Product Vision

## 1. 목적

WELLB OPENLAB이 해결하려는 문제, 제공 가치, 장기 방향과 제품 불변 조건을 하나의 기준으로 정의한다. 기능·화면·AI 동작·운영 정책이 본 문서와 충돌하면 구현보다 본 문서를 우선한다.

## 2. 제품 정의

> WELLB OPENLAB은 사용자가 생활·업무·지역사회에서 발견한 문제와 아이디어를 AI 코치의 도움으로 구조화·시각화하고, AI·사용자·현장 전문가의 다층 검토를 거쳐 실증 가능한 제안으로 발전시키는 AI 증강 오픈이노베이션 플랫폼이다.

제품은 일반적인 챗봇, 자유제안 게시판, 인기투표형 공모전, AI 자동 사업계획서 생성기가 아니다.

## 3. 해결하려는 구조적 문제

| 현재 문제 | WELLB OPENLAB의 전환 |
|---|---|
| 문서 작성 역량이 좋은 사람이 유리함 | AI 질문과 표준 구조로 참여 장벽을 낮춤 |
| 해결책부터 제안해 실제 문제가 불명확함 | 문제·대상·맥락·근거를 먼저 구조화 |
| 제안 형식이 달라 비교가 어려움 | Idea Passport로 비교 가능한 자산화 |
| 좋아요·인지도·심사위원 취향에 좌우됨 | AI·현장 사용자·전문가를 분리한 다층 평가 |
| 수상 후 후속 실행이 없음 | 30일 실험, Proof Day, Pilot로 연결 |
| 아이디어와 평가 데이터가 사라짐 | 버전·근거·평가·실증 결과를 지속 축적 |
| 취약계층과 현장 당사자가 배제됨 | 쉬운 참여와 당사자 검증을 기본 설계로 적용 |

## 4. 핵심 가치 제안

### 참가자

막연한 문제의식을 빈 문서 없이 시작하고, AI가 던지는 질문을 통해 자신의 생각을 실행 가능한 아이디어로 발전시킨다.

### 기관·기업

자유제안함이나 일회성 공모전을 반복 가능한 혁신 파이프라인으로 바꾸고, 비교 가능한 제안과 실증 후보를 확보한다.

### 현장·지역사회

문제 당사자와 전문가가 평가와 실증에 참여해 실제 필요에 가까운 해결안을 선별한다.

### WellB Company

AI 에이전트·오픈이노베이션 운영·소셜 임팩트·지역 AX 역량을 하나의 대표 제품과 반복 가능한 레퍼런스로 축적한다.

## 5. 제품 원칙

### Human-originated

사용자의 경험과 판단이 아이디어의 출발점이다. AI는 질문·정리·대안 비교·검토를 돕지만 사용자 동의 없이 내용을 확정하지 않는다.

### Evidence-aware

사실, 경험, 가정과 기대효과를 구분한다. 출처 없는 수치나 성과를 생성하지 않는다.

### Execution-oriented

화려한 문서보다 30일 안에 핵심 가정을 검증할 수 있는 제안을 우선한다.

### Transparent evaluation

평가 기준, 점수, 근거, 확신도, 평가 주체와 이해상충을 기록한다. AI는 최종 결정자가 아니다.

### Inclusive by design

쉬운 문장, 단계별 질문, 키보드 접근, 명확한 상태 안내와 시각화의 텍스트 대체를 기본으로 한다.

### Rights-respecting

아이디어 소유권은 원칙적으로 제출자에게 유지된다. 실증·공동개발·양도·독점 사용은 별도 계약이 필요하다.

### Sponsor-bounded

스폰서는 프로그램의 지속성과 확산을 지원하지만 비공개 아이디어의 자동 열람권, 소유권 또는 최종선발 단독권을 갖지 않는다.

## 6. 핵심 제품 루프

```text
문제 발견
→ AI 지원 구조화
→ Idea Passport
→ Preflight
→ 제출 버전 고정
→ AI·현장·전문가 평가
→ 고도화
→ Pilot
→ 검증 결과 축적
→ 다음 Monthly Challenge 개선
```

## 7. 장기 비전

WELLB OPENLAB은 제주에서 시작해 기관·기업·지역사회가 반복적으로 사용할 수 있는 다음 운영체계로 발전한다.

1. 시민·임직원의 문제와 아이디어를 비교 가능한 데이터로 전환
2. AI와 사람의 판단 차이를 학습 가능한 평가 자산으로 축적
3. 가능성 있는 아이디어를 현장 실증과 AX 프로젝트로 연결
4. 월간 챌린지의 누적 결과를 지역·산업 인사이트로 발행
5. 기관별 전용 OpenLab과 화이트라벨 서비스로 확장

## 8. 북극성 지표

**Pilot-ready Idea Rate**

```text
Pilot-ready로 승인된 아이디어 수
÷ 최종 제출된 적격 아이디어 수
```

이 지표는 제출량보다 실제 실험 가능한 수준으로 발전한 비율을 본다. 상세 정의는 `success-metrics.md`를 따른다.

## 9. 비목표

- AI가 독창적 아이디어를 대량 생성하는 서비스
- 좋아요 수로 우승자를 자동 결정하는 커뮤니티
- 특허·투자·사업 성공을 보장하는 서비스
- 제출 즉시 아이디어를 법적으로 보호하는 서비스
- 스폰서의 홍보 콘텐츠만 생산하는 캠페인
- 모든 아이디어를 공개하도록 강제하는 플랫폼

## 10. 불변 조건

- AI 제안은 사용자 확인 전 canonical 데이터가 아니다.
- 제출 버전은 평가 중 불변이다.
- AI 점수만으로 자동 탈락시키지 않는다.
- 비공개 콘텐츠는 승인된 역할과 목적 외에 노출하지 않는다.
- JDC 관계는 공식 협약 전까지 `proposal` 상태다.
- 실증·사업화에는 별도 동의와 계약이 필요하다.

## 11. Acceptance Criteria

- 제품 설명이 참가자·기관·평가자 관점에서 서로 모순되지 않는다.
- 핵심 사용자 여정이 Challenge에서 Pilot까지 연결된다.
- AI, 권리, 평가, 스폰서 경계가 문서에 명시된다.
- MVP 기능이 제품 비전의 어느 문제를 해결하는지 추적할 수 있다.
- 비목표가 향후 Feature 요청을 판단하는 기준으로 사용된다.
